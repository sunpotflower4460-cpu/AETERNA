# Topological Observation Lens

## Status

This is an optional observation lens for future AETERNA phases.
It is not a runtime physics implementation.

This document exists to prevent a useful mathematical analogy from becoming an overclaim.

## Purpose

Sphere eversion and related smooth constrained transformations are useful as analogies for observing:

- wave freedom before deformation
- phase circulation
- path overlap in internal state space
- inside/outside mediation
- smoothing / relaxation after deformation

They are not used as proof of life, consciousness, selfhood, or torus necessity.

## Strict non-goals

AETERNA must not:

- implement sphere eversion as the physical engine
- claim that life equals sphere eversion
- claim that a torus is a mathematically required intermediate state for life
- claim that Morin-surface-like geometry is being reproduced
- use topological symmetry seeds as the default dynamics
- use winding number as a life detector

## Safe interpretation

A safe statement:

```text
Sphere eversion is used as a metaphor for smooth constrained transformation with self-overlap allowed in a mathematical setting.
AETERNA may borrow observation questions from this analogy, such as whether phase circulation or path overlap appears in internal field dynamics.
```

Unsafe statement:

```text
AETERNA proves that life emerges through sphere eversion.
```

## Lens 1: corrugation-like wave freedom

Sphere eversion visualizations often begin by giving the surface wave-like freedom before large deformation.

AETERNA translation:

```text
Do not move directly from a rigid scalar state to closure claims.
First provide wave-capable medium, phase-carrying drive, and explicit drive-to-wave accounting.
```

Implementation implication:

- v5.1 drive-to-wave completion remains required before v6 nonlinear/boundary phases.
- Wave freedom is not a visual effect; it must be represented through explicit fields and accounting.

## Lens 2: phase circulation observation

AETERNA may observe local or loop-level phase circulation in complex/phase fields.

Recommended names:

- `phaseWindingObservation`
- `phaseCirculationIntegral`
- `phaseDefectCandidate`

Forbidden names:

- `lifeWinding`
- `targetWinding`
- `forceWinding`
- `stabilizeWinding`

Rules:

- phase circulation is observer-side only
- it must not control runtime dynamics
- it must report residual / ambiguity where a loop is incomplete
- it must not be interpreted as proof of closure or life

## Lens 3: phase path overlap observation

Sphere eversion permits self-intersection in the mathematical surface immersion.

AETERNA should not translate this as physical self-intersection.
Instead, it can observe whether different phase paths, time traces, or flow routes overlap in internal state space.

Recommended names:

- `phasePathOverlapObservation`
- `stateSpaceCrossingCandidate`
- `pathOverlapDiagnostic`

Rules:

- overlap is observed, not created
- overlap does not imply selfhood
- overlap does not imply meaning
- overlap must not be used to increase coherence or stability

## Lens 4: topological symmetry seed scenarios

Symmetry seeds may be useful as comparison scenarios.
They must not be default initial conditions.

Allowed:

```text
Compare random phase seeds with symmetric phase seeds and report how phase circulation, overlap, and transfer residual differ.
```

Forbidden:

```text
Initialize the system with a Morin-like seed to make it look like sphere eversion.
```

Scenario rule:

- topological symmetry seed is a benchmark scenario
- random seed, zero seed, and null model comparisons must remain available
- if the symmetry seed looks more organized, it is a scenario result, not proof

## Relationship to the main roadmap

This lens belongs after the core v6 accounting path is documented and at least previewable.
It may be referenced in v6 docs, but it should not reorder the physical implementation path.

Preferred order:

```text
v6 charter
v5.1.4 work-term preview
v5.1.5 applied transfer
v6.0 nonlinear potential
v6.1 boundary phase field
v6.5 closure observatory
then topological observation reports
```

Use:

- observed phase circulation
- phase overlap candidate

Avoid:
